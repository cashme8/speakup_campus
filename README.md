# SpeakUp Campus

SpeakUp Campus is a Flutter app for reporting problems around campus, such as
broken taps, power cuts, damaged furniture or safety concerns, and following
them until they are fixed. Students submit reports, and campus staff review
them and move them from **Submitted** to **In Progress** to **Resolved**, with
a note at each step.

**Stack:** Flutter · Provider · Firebase Authentication · Cloud Firestore ·
Supabase Storage (photos)

Full documentation, including the architecture, data model, security rules,
the Firebase–Supabase connection and the test plan, is in
[docs/DOCUMENTATION.md](docs/DOCUMENTATION.md).

## Features

- Sign up only with an ALU email (`@alustudent.com` or `@alueducation.com`),
  plus **email verification** before anything else in the app opens
- Report an incident with a category, title, description, campus area, room
  and an optional photo (camera or gallery)
- **Anonymous reporting**: the reporter's name is never saved on the report
- **Duplicate warning**: before submitting, the form shows reports that are
  already open at the same location
- **"Me too"**: students can confirm someone else's report instead of filing a
  new one
- Browse **My reports** or the whole **Campus**, search, and filter by status
  and category
- Live status timeline and activity log with staff notes
- Only staff can change a status. This is enforced by the Firestore security
  rules, not just hidden in the UI
- Reporters can withdraw a report while it is still *Submitted*

## How the backend fits together

```
                    ┌─────────────────────────┐
                    │   Flutter app (Provider)│
                    └───────┬─────────┬───────┘
          sign in / ID token│         │photo upload + Firebase ID token
                            ▼         ▼
┌──────────────────────────────┐   ┌──────────────────────────────┐
│ Firebase                     │   │ Supabase Storage             │
│  • Authentication (identity) │   │  bucket: incident-photos     │
│  • Firestore (users,         │   │  policies check the Firebase │
│    incidents, security rules)│   │  token: uid, verified, ALU   │
└──────────────────────────────┘   └──────────────────────────────┘
                 ▲                                  │
                 └──── incident stores imageUrl ────┘
```

- **Firebase Authentication** is the only login system. Supabase has no
  accounts of its own.
- **Firestore** stores users and incidents and updates every screen in real
  time.
- **Supabase Storage** stores the photos. The app sends the user's Firebase ID
  token with each upload (Supabase *third-party auth*), and the bucket policies
  only accept verified ALU users writing into their own folder.
- I chose Supabase for photos because new Firebase Storage buckets now need
  the paid Blaze plan. Storage sits behind a `PhotoStorage` interface, so
  switching back to Firebase Storage is a one-line change in `main.dart`.

## Running the app

Requirements: Flutter (stable, Dart 3.13 or newer; I developed on Flutter
3.47) and an Android emulator or device.

```bash
flutter pub get
flutter run
```

The repository is already connected to my Firebase project (`speakup-campus`)
and my Supabase project, so it runs as is. To connect your own projects, follow
the setup guide in [docs/DOCUMENTATION.md](docs/DOCUMENTATION.md#7-setting-up-the-backend-from-scratch).
In short:

1. **Firebase:** create a project, enable **Email/Password** sign-in and
   **Firestore**, run `flutterfire configure`, then
   `firebase deploy --only firestore:rules`.
2. **Supabase:** create a project and a **public** bucket called
   `incident-photos`, run `supabase/storage_policies.sql` in the SQL Editor,
   and under **Authentication → Third-Party Auth** add **Firebase** with your
   Firebase project ID.
3. Put your Supabase URL and publishable key in `lib/supabase_config.dart`.

## Creating a staff account

Nobody can register as staff from the app, because the rules force
`role: 'student'` on sign-up.

1. Register in the app with an ALU email and verify it.
2. In the Firebase console, go to Firestore → `users/{uid}` and change `role`
   to `staff`.
3. The app switches to the staff view straight away, because the profile is
   a live listener.

## Tests

```bash
flutter test
```

28 tests: unit tests for both providers, and widget tests that run the real
screens through registration → verification → home, submitting a report,
browsing, signing out and a staff status update. They use in-memory fakes, so
they need no network or Firebase.
