# SpeakUp Campus

A Flutter app for reporting campus issues (water, electricity, facilities,
safety, sanitation, furniture) and tracking them from **Submitted** →
**In Progress** → **Resolved**. Students file and follow reports; authorised
staff review them and update their status with notes.

Built with **Flutter**, **Provider**, **Firebase Authentication**,
**Cloud Firestore** and **Firebase Storage**.

## Features

- ALU-only accounts (`@alustudent.com`, `@alueducation.com`) with **email verification**
- Report an incident: category, title, description, campus area + room, optional photo
- **Anonymous reporting** – the name is never stored on the report
- **Duplicate warning** – shows open reports at the chosen location
- **"Me too"** – confirm an existing report instead of filing a duplicate
- Browse **My reports / Campus**, search, filter by status and category
- Live status timeline and activity log with staff notes
- Staff-only status updates, enforced by **Firestore security rules**
- Reporters can withdraw a report while it is still *Submitted*

## Architecture

```
lib/
├── main.dart                 Firebase init, dependency injection, AuthGate
├── firebase_options.dart     generated by flutterfire configure
├── data/
│   ├── repositories.dart              abstract interfaces (AuthRepository, IncidentRepository, PhotoStorage)
│   ├── firebase_auth_repository.dart  Firebase Auth + users/{uid}
│   ├── firestore_incident_repository.dart
│   └── firebase_photo_storage.dart
├── models/                   AppUser, Incident, StatusEntry (no Firebase imports)
├── providers/                AuthProvider, IncidentProvider (ChangeNotifier)
├── screens/                  auth/, home, reports, report form, detail, profile
├── widgets/                  reusable UI components
├── theme/ utils/             design tokens, validators, formatting
test/
├── support/fakes.dart        in-memory repositories used by all tests
└── *_test.dart               provider unit tests + widget flow tests
```

UI → Providers → Repository interfaces → Firebase. Providers never import
Firebase, so tests swap in fakes and run without a network.

## Firestore data model

```
users/{uid}
  name, email, department, role ('student' | 'staff'), createdAt

incidents/{incidentId}
  title, description, category, location, locationDetail?
  status ('submitted' | 'inProgress' | 'resolved')
  reporterId, reporterName (null if anonymous), isAnonymous
  affectedBy [uid], imageUrl?, imagePath?
  createdAt, updatedAt (server timestamps)
  history [{status, at, note?, byName?}]
```

Photos: `incident_photos/{uid}/{incidentId}.jpg` in Firebase Storage.

## Running the app

Requirements: Flutter stable with Dart 3.13+ (developed on Flutter 3.47), an
Android emulator or device.

```bash
flutter pub get
flutter run
```

To use your own Firebase project instead:

1. Create a project; enable **Authentication → Email/Password**, **Firestore**, **Storage**.
2. `dart pub global activate flutterfire_cli` then `flutterfire configure`.
3. Deploy the rules: `firebase deploy --only firestore:rules,storage`.

## Creating a staff account

Nobody can register as staff from the app (the rules force `role: 'student'`).

1. Register in the app with an ALU email and verify it.
2. In the Firebase console → Firestore → `users/{uid}`, change `role` to `staff`.
3. The app switches to the staff view immediately (the profile is a live listener).

## Tests

```bash
flutter test
```

Unit tests cover the providers (roles, filters, privacy labels, photo upload
rollback, staff-only updates); widget tests drive the real screens through
registration → verification → home, reporting, browsing and a staff status update.
